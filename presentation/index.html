Problem

The problem we are solving

🏛️

Manual, paper-based process

Citizens visit government offices multiple times, fill paper forms, and wait weeks for approval with no visibility into their application status.

⏳

No transparency or tracking

Once a form is submitted, citizens have no way to know its status, what stage it is in, or what additional information may be required.

Reference: Irembo (irembo.gov.rw) — Rwanda's existing e-government platform — shows that this problem is solvable at national scale.
✅

Our solution — BizReg

A fully online registration platform. Citizens apply from home, track status in real-time, pay online, and download a digital certificate — without visiting any office.

Key design decisions:
UUID primary keys throughout for security (no sequential ID guessing). Passwords stored as bcrypt hashes — never plaintext. Audit logs are append-only — no UPDATE or DELETE ever touches them.

Relationships

A citizen can submit many applications. Each application belongs to one service, has one payment, many documents, many notifications, many workflow tasks, and an immutable audit trail.

Workflow

Application Lifecycle — State Machine

Every transition is server-enforced. No client can skip a state. Every transition creates an immutable audit log entry and queues a notification.

Security

Security by Design

  • bcrypt password hashing — 12 rounds, never stores plaintext passwords
  • JWT Bearer tokens — HS256, 30-min access + 7-day refresh
  • Live token validation — every request re-queries the database (catches deactivated accounts)
  • RBAC — require_role() factory guards every endpoint
  • Object-level auth — citizens can only access their own applications
  • Rate limiting — 200 requests/min per IP via slowapi
  • CORS — explicit origin, method, and header allow-lists
  • Input validation — Pydantic v2 schemas on every endpoint
  • File validation — MIME type, extension, 10 MB max server-side
  • Audit trail — append-only log on every state transition
  • Secrets management — env vars only, never hard-coded
  • Non-root Docker — both containers run as non-root users
  • React hydration safety — localStorage read deferred post-mount
  • OWASP CI check — dependency vulnerability scanning on every push

Reflection

Key Learnings

🏗️

Full-stack integration

Building a feature end-to-end — from DB schema → ORM → REST endpoint → React page — taught how all layers interact in a real production system.

🔐

Security first

Security is not an afterthought. JWT, RBAC, bcrypt, audit logs, rate limiting, and file validation were built in from Day 5 and applied consistently throughout.

🔄

State machine thinking

The workflow engine taught how to model real-world processes as finite state machines with server-enforced transitions and complete audit history.

🐳

DevOps practices

Docker, CI/CD, GitHub Actions, multi-stage builds, and environment-based configuration are not "advanced" — they are essential for any real project.

Most important insight: A public service platform must prioritise trust above all else. Citizens sharing personal and business data deserve strong security, transparency through audit trails, and reliability through automated testing and deployment pipelines.
